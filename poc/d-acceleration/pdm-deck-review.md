# PdM 企画書のレビュー（作った文脈を持たないレビュアー向け）

作った本人には見えない破綻（言い回し、論理の飛び、タイトルと図の食い違い、根拠のない評価語、
数字のずれ）を、作り方を知らない別のレビュアーに拾わせる。`pdm-deck.py check` と `build` の
指摘を直したあと、人に渡す前に通す。

## 渡し方

1. `python3 -I {{HARNESS_DIR}}/tools/d-acceleration/pdm-deck.py outline --spec <pdm-deck>/deck.json`
   の出力をファイル（`<pdm-deck>/outline.md`）に書く。タイトルの通し読みと、各ページの中身のテキスト。
2. 下の「依頼文」を、**作り方・使った材料・こだわった点を伝えずに**、新しいレビュアーに渡す
   （ハーネスが別のエージェントを起動できるならそれを使う。起動できないなら、このレビューは飛ばし、
   飛ばしたことを一行で伝える）。`{FILE}` は outline のパス、`{N}` はページ数に置き換える。
3. 返ってきた指摘を 1 件ずつ「直す／直さない（理由）」に分け、直すものを spec で直して
   `check` と `build` をやり直す。意味や結論が変わる直し（主張の言い換え、ページの統合、数字の差し替え）は、
   直す前に AI-DLC の質問の流れで人に確かめる。
4. 何を指摘され、何を直し、何を直さなかったかを `<pdm-deck>/review.md` に表で残す
   （ページ、指摘、種類〔日本語・論理・数字・体裁〕、対応）。

## 依頼文

あなたはサービス企画書のレビュアーです。{N} ページの企画書の本文が `{FILE}` にあります。
どう作られたかは知らされません。ファイル全体を読み、全ページを順に確かめてください。ほかのファイルは
読まないでください。

まず、決裁者として読んだときに一番困ること、納得できないこと、突き返す理由を、思いつく順に 3〜10 件
自由に書いてください。

次に、ページ番号と該当箇所の引用を付けて、次を挙げてください。

- **日本語**: 引っかかる言い回し、主語や述語の抜けた詰め込み語、語尾のそろわない箇条、定義のない略語、
  同じものの表記ゆれ。言い換え案も書く。
- **論理**: タイトルだけを上から読んで、話が飛ぶ・戻る・同じことを二度言う・前提なしに結論が出る箇所。
  ページの中で、左の事実から右の示唆が導けない箇所。
- **食い違い**:
  1. タイトルの数（「3つの層」）と本文の数が合わない
  2. タイトルの結論と図・表の中身が合わない
  3. 「十分」「限定的」「問題ない」などの評価語に、そのページの中で根拠がない
  4. 後ろのページが前のページの言い直しで、新しい論点がない
  5. サマリーや目次の予告と本編が合わない（ページ番号の参照も）
  6. 同じ数字がページによって違う、合計が合わない、単位や期間が途中で変わる
  7. 数字のあるページに出典や前提（注）がない
  8. 業界・法令・制度の用語の使い方が、その分野の定義と違う
- **未検討の扱い**: 未検討・一部未検討のページを見て、意思決定の前に埋めるべきものと、後でよいものを分ける。

最後に、7 つの観点を各 10 点で採点し、理由を 1〜2 文ずつ書いてください。観点は、
話の通り、1 ページ 1 メッセージ、情報の形（比較・因果・推移が表・図になっているか）、説得力
（決裁者がそのまま判断に使えるか）、一貫性（用語・数字・体裁）、誠実さ（出典・前提・限界の書き方）、
網羅（PdM が検討すべき観点の漏れ）。そのうえで、直すべき順に 5 件、どう直すかまで書いてください。

盛らずに書いてください。欠点を最低 3 つ挙げてください。
