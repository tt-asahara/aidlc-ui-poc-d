用語（3行で）

engine＝決定論のオーケストレーションエンジン（aidlc-orchestrate.ts next / report。ルーティング・状態遷移・監査を所有）。 conductor＝/aidlc skill を実行する LLM セッション（engine に次の一手を聞き、ステージ本体の知識労働を行う）。 tool＝bun .claude/tools/aidlc-*.ts（core の決定論ツール）。D 拡張は .claude/tools/d-acceleration/、UI 基盤（Arm C）は .claude/tools/ui-poc-*.cjs に置かれ、native 版では aidlc d <tool> で呼ぶ。

① /aidlc コマンド × 33ステージ マトリクス

縦が /aidlc に続けて打つ全コマンド（core 20＋D 拡張 6、＋独立 skill 1）、横が33ステージ。●＝そのステージの成果物を直接読み書きする確定的な対応、◎＝ステージ範囲に緩く対応する概念上の紐付け、帯塗り＝ステージを問わず全体に効く／毎回対象を指定する。行をクリックすると下に構文・使用例・詳細・参照資料・編集する成果物が開く。

core が確定的に対応 D 拡張が確定的に対応 範囲に緩く対応（概念上） 全ステージ共通 任意指定（毎回対象が変わる）

列の色はフェーズ配色（紫=Initialization／青=Ideation／藍=Inception／緑=Construction／桃=Operation）。行見出し左の縦線（緑=core／橙=D 拡張）がコマンドの出自。

② コマンドではなく自動発火するイベント

①は人間が明示的に打つ入口。これとは別に、ステージ境界・ゲート・Bash 呼び出しでコマンド無しに発火する処理がある。「自動」に見えて既定オフ（オプトイン）のものが混在するので、行の色で区別する: 緑＝既定オン／橙＝既定オフ／グレー＝自動発火なし（手動必須）。

③ D 設定一覧（.claude/d-acceleration.jsonc）

PRODUCT の .claude/d-acceleration.jsonc を読み、.claude/d-acceleration.local.jsonc がフィールド単位で上書きする（local が優先）。ファイルが無ければすべて既定値。ひな形は .claude/tools/d-acceleration/d-acceleration.example.jsonc（各スイッチの直前に日本語で対象・ON/OFF 時の挙動・既定値・利用場面が書いてある）。追加機能・Issue オートパイロット・自動進行はすべて既定オフ。実効値は run.ts --preflight で確かめる。

グループキーと既定値何を制御するか
modelsfast / balanced / judgment: "opus"D が起動する並列 worker のモデル（tier 別）。親セッションのモデルは変えない
parallelenabled: trueD の並列処理の親スイッチ（②参照）。OFF は即時反映、ON は次の D 起動から
constructionDefaultsiteration: "stage-major"・execution: "swarm"--auto が作った新規 intent の Construction 歩行順と実行方式（②参照）。swarm には stage-major が必要
gitPersistenceenabled: false・push: false・remote: "origin"承認済み遷移の checkpoint commit と push（②参照）。secret scan 自体には OFF スイッチが無い
featuresrequirementIdValidation・functionalDesignDocumentDiscipline・sourceGrounding・specGrounding・mockupPngGeneration・visualRegression・prLensReview: すべて false任意の検査・補助レビュー（②参照）。visualRegression を ON にすると基準 PNG 生成も有効になる
featureInputsrequirementIdBridges: []・functionalDesignBudgets（60000 / 160000 / 30000 byte）・sourceRoots: []・specRoots: []・groundingLimits（200 file / 1,000,000 byte）features の入力。bridge は旧形式 AC-… の契約だけに使う。grounding は明示した root だけを読み、空のまま ON にすると NOT-READY を記録する
uiDesignrefinedMockupSkill: "impeccable-historical"2.5 refined-mockups のデザインスキル。選択肢は impeccable-historical（既定・Arm C）／impeccable（4.6.0）／ui-ux-pro-max／ponta-pass-design（Pontaパス デザインシステム）。既定以外は事前に setup-design-skill.ts で導入が必要で、ui-poc-comparison では拒否される
autoenabled: false・through: "code-generation"・sessionOnly: true・ambiguityPolicy: "halt"・assumptionLedger: true・maxRetries: 2・maxSteps: 64・deadlineMs: 900000・labelAllowlist: []自動進行の親スイッチと上限。sessionOnly: true は intent 作成で止まる。ambiguityPolicy は halt（止まる）／assume（仮定を台帳に記録して進む）／research（調べても不明なら止まる）。assumptionLedger: false なら常に halt 扱い。deadlineMs は人の待ち時間を数えない。空の labelAllowlist は「許可なし」

aiApprovalmode: "human"・minConfidence: 0.9委任された低リスク質問への AI 回答（②参照）。旧 decisionRecordPath は削除済みで、書くと設定エラー
decisionIssueSummaryenabled: false・repository・send: false・maxRetries: 2AI 判断の Issue 要約（②参照）。repository は owner/name か HOST/owner/name（GitHub Enterprise）
core 側の実行設定（depth・test-strategy・review・guard-policy・sensors など）は従来どおり /aidlc config get|set|list と①の各フラグで変える。D の設定ファイルはそれとは別で、D が足した機能だけを制御する。

④ scope 一覧（15種）

scope はステージ集合＋depth＋test-strategy のプリセット。/aidlc <scope名> または説明文からの自動判定で決まる。ui-poc-* の3つは UI 基盤プラグイン（poc/ui-poc）の scope で、D の導入で使えるようになる。短い英語の依頼（web app・dashboard など）は ui-poc-application に自動判定されるが、長文や日本語の依頼は通常の提案になるので、scope 確認で ui-poc-application を選ぶ。

⑤ GitHub 連携とラベル

D にはラベルの正本カタログもラベルガードも無い（KDDI 配布の aidlc:* 10個・github-setup・github.autoSync の Milestone / Issue 投影は持ち込んでいない）。GitHub に触れるのは次の3つだけで、どれも既定オフ。

入口使うラベル・設定挙動
/aidlc-issue-autopilot <label>auto.labelAllowlist（完全一致）許可リストのラベルを持つ open Issue を、番号の昇順で1回1件。ラベル名はチームが決める（例: aidlc-auto）。空配列なら何も処理しない
/aidlc --next-intent --from-issue <N>
/aidlc --auto --through <s> --from-issue <N>		同上番号を指定して1件だけ intent 化する。同じ Issue の intent が既にあればそこから再開する
decisionIssueSummaryrepository・sendintent ごとの AI 判断要約 Issue を1つ作成・更新する。未解決事項の別 Issue は作らない
GitHub に触れる前に必ず gh auth status --hostname <host> を確認し、そのホストに未ログインなら gh-auth-required で止まって gh auth login --hostname <host> を案内する。github.com と GitHub Enterprise（例: github.kddi.com）は別扱いで、片方のログインでは満たさない。
